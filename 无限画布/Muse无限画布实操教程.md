# Muse＋无限画布实操教程

> 实操教程 · 从角色图到视频成片 · 约 6 分钟读完 · 零剪辑经验可跟做

核心思路只有一句话：**你只负责提目标、看结果、给反馈；Agent 负责搭工具、写分镜、编排任务；Muse 负责生图和生视频；无限画布负责把所有素材和它们的来历存成一个工程。**下面用原作者做出的 18 秒短片《别开门》把全流程拆开。

## ① 先看成片：《别开门》（18 秒 · 3 个镜头）

- **镜头 1 · 雨夜 · 破庙外**：场景图先行：雨夜、破庙、氛围定调，后续所有镜头都从这张场景长出来。
- **镜头 2 · 双人镜头 · 首帧先行**：两位角色的定妆图合成双人首帧，再拿首帧去生视频。这张曾超时，只重跑了这一张。
- **镜头 3 · 推进 · 留悬念**：第三个镜头收束剧情，三段视频进本地时间线、加上剧情字幕，拼成完整小样。

成片构成：2 位角色定妆图 · 1 张场景图 · 3 张分镜首帧 · 3 段生成视频 · 0 行手写剧本（作者本人）

作者要验证的不是“能不能生成一段视频”，而是：一个没有视频制作经验的人，能不能只靠提需求＋看结果＋反馈，把工具组合起来完成一次创作。结论是能跑通，但成片仍有瑕疵，见文末局限部分。

## ② 五方分工：先分工，后动手

搞不清谁干什么，后面每一步都会乱。整条链路一共五个角色：

- **你（导演 / 甲方）——做决定的人**：提出目标、看效果、纠正方向，确认哪个任务要重试。做什么内容、想怎么展示，只有你能定。
- **Codex（Agent · 编排者）——干活的人**：安装和接入工具，写剧情、角色设定与分镜提示词，在画布上搭节点、编排生成任务，接口不匹配时做适配。
- **Muse（生成引擎）——出图 / 出视频**：真正生成图片和视频的是它。画布里发起的每个任务，在 Muse 网页里都能找到对应的生成记录，可逐条核对。
- **无限画布（BeefTV · 工程管家）——存素材 / 存关系**：保存角色图、场景图、首帧、视频和时间线，并用连线记录“谁参考了谁”。换其他画布时，接法不能直接照搬，要逐项核对导入、参考关系、模型接入和剪辑能力。
- **muse2api（第三方桥接）——只负责转交**：把画布的提示词、参考图等请求转交给 Muse，等生成完成再把结果送回画布。它不生成内容，消耗的是你自己 Muse 账号的额度，也不是官方提供的免费 API。

## ③ 一张画布，就是整个工程

《别开门》的真实画布是左 → 中 → 右的流水线：左边定“人”和“景”，中间定每一镜的画面，右边出视频和成片。

传递顺序：**角色图 ＋ 场景图 → 分镜首帧 → 视频 → 时间线成片**

### 左 · 角色与场景

- **角色 A 定妆图**（图片 · Muse 生成）：文字设定 → 生成，作为身份参考。由 Codex 先写好角色文字设定，再经 Muse 生成。它是后面所有双人镜头的身份锚点——换掉它，所有首帧都要重做。
- **角色 B 定妆图**（图片 · Muse 生成）：与 A 同风格，组成双人关系。与角色 A 同批生成、同一画风。双人镜头靠这两张图合成，人物的小痣、疤痕等细节在后续环节可能漂移，要有心理预期。
- **场景图 · 雨夜破庙**（图片 · Muse 生成）：统一三个镜头的环境与光线。先定场景再定镜头。所有首帧都引用这张图，门窗位置等细节如果漂移，多半是这一步的参考权重问题。

### 中 · 分镜首帧

- **镜头 1 首帧**（首帧 · 参考合成）：角色图 + 场景图 → 合成。角色图 + 场景图共同参与生成。首帧不是终点图，它还要作为视频任务的参考输入，所以构图要给运动留空间。
- **镜头 2 首帧 · 双人**（首帧 · 曾超时重跑）：超时后单独重跑，其余保留。本工程唯一出过问题的节点——第一次生成超时。处理方式是只重跑这一张，已成功的镜头 1、3 全部保留，不整批重来。
- **镜头 3 首帧**（首帧 · 参考合成）：生成后先验图，再送视频。收束镜头的画面。和前两张同批检查：人物长相、场景细节有没有漂移，在这一步拦下来成本最低。

### 右 · 视频与成片

- **视频 × 3**（视频 · 图生视频）：首帧 → 视频，带动作要求。每张首帧各生成一段视频，提示词里写动作要求。这些任务在 Muse 网页端都有对应记录，可以拿画布结果逐条对照核对。
- **时间线 → 《别开门》**（成片 · 00:18）：拼接 + 字幕，可回溯每一镜。三段视频进入本地时间线，加上剧情字幕，拼成 18 秒小样。工程里保留可编辑时间线，改任何一镜都能顺着连线找回它的参考图和提示词。
- **连线 = 参考关系**（理念）：每条线都是一次真实的素材传递。某个镜头不满意时，不用猜——顺着连线就能找到它用了哪张参考图、哪条提示词、哪次任务。修改是定点修改，不是推倒重来。

## ④ 部署：在 MacBook 上把三件套跑起来

整套东西都在你自己的 MacBook 本地运行，不用租服务器。顺序是：先装画布 BeefTV，再用 Docker 跑 muse2api，然后导号、接入、验证。装的过程也可以直接交给 Agent 做（指令在第 06 节），下面是手动核对用的步骤。

### 1. 装 BeefTV（无限画布）

去 BeefTV 的 GitHub 仓库 Releases 页下载 Mac 桌面版安装包（链接在文末）。这个安装包没有经过苹果公证，第一次双击打不开是正常的。

- **你做**：下载并安装；被系统拦下时，去「系统设置 → 隐私与安全性」，在页面下方点「仍要打开」，再确认一次。
- **✓ 检查点**：打开后直接进入本地工作区，不需要注册账号，能新建一张空白画布，就算装好了。

### 2. 用 Docker 跑 muse2api

先装好 Docker Desktop 并确认它在运行，然后打开「终端」，依次执行下面四行：

```bash
git clone https://github.com/czg86389-hub/muse2api.git
cd muse2api
cp .env.example .env
docker compose up -d
```

- **你做**：打开刚复制出的 `.env` 文件，把 `MUSE2API_KEY` 填成一串你自己定的密码（随便一串字符即可，记住它，下一步要用），保存后重新执行一次 `docker compose up -d`。
- **✓ 检查点**：浏览器打开 `http://localhost:18610/admin?key=你填的KEY`，能看到 muse2api 控制台，服务就是起来了。

### 3. 导号：把 Muse 登录态导进去

muse2api 本身不生成内容，它要借你已登录的 Muse 网页账号干活，所以要把登录态导给它。

- **你做**：按 muse2api 项目文档装好它配的 Chrome 扩展，在浏览器里保持 Muse 网页为已登录状态，用扩展把登录态导入 muse2api。
- **✓ 检查点**：控制台里能看到账号已接入。登录态 48 小时自动续期，过期或失效时重新导一次即可。

### 4. 在 BeefTV 里接入，再验证

最后把画布和桥接连起来：在 BeefTV 的模型配置里，把 Muse 的图片、视频生成指向 muse2api 的本机地址 `http://localhost:18610`。

- **你做**：填好地址和第 2 步定的 KEY，保存配置。涉及账号额度的生成提交，先自己确认再发。
- **✓ 检查点**：先在画布里生成一张图片，能出图；再发一个视频任务，能返回结果。两个都通，部署才算完成，接下来按第 05 节五步实操开做。

**跑起来之后，三件事别忘**

- MacBook 睡眠或合盖会断掉本地服务，生成跑到一半别合盖。
- 18610 端口只在本机用，不要对外暴露。
- muse2api 是第三方桥接、不是官方 API，消耗的是你自己 Muse 账号的额度，这类接入方式本身有封号风险，先想清楚再用。

## ⑤ 五步实操

原文的真实顺序。注意第 2 步的“跑偏”不是失败——先拿一个小测试跑通链路，再纠正方向，是这套方法的一部分。

### 1. 让 Agent 把工具搭起来

作者的起点是：看到别人演示 Muse＋无限画布，自己已有 Muse 账号，想在本地复现。他把目标告诉 Codex 并选了“直接安装 BeefTV、接入 Muse”，之后的安装、接口检查都由 Agent 处理；这次视频接口的请求格式并不直接匹配，也是 Agent 做的适配。

- **你做**：说明目标和已有条件（有 Muse 账号、画布用 BeefTV），按提示配合完成工作区连接与本机账号接入。
- **AGENT 做**：读 BeefTV 与 muse2api 的当前文档，检查电脑环境与接口兼容性，完成安装与适配。
- **✓ 检查点**：先验证一张图片能生成，再验证一个视频任务能返回。两个都通，才算接通。涉及账号额度的提交，先经你确认。

### 2. 自动建画布，先跑一次完整测试

接通后先别急着做正片。作者让 Codex 自动建画布，跑了一轮文生图＋图生视频，产物是一组咖啡广告：产品图、海报和一段视频，提示词与结果都留在画布里——目的是验证整条链路真的通。

- **你做**：给一个简单、好判断对错的测试题（比如一个产品广告），看完整结果。
- **AGENT 做**：建画布、组织节点、发起生图与生视频任务，全程走 Muse 的模型。
- **✓ 检查点**：图能出、首帧能喂给视频、视频能回到画布。三件都成立再进下一步。

### 3. 看结果，把方向说具体

咖啡广告跑通了，但不是作者想要的。他给的反馈是两句很具体的话：想要“真人漫剧型”的内容；并且希望有真实的画布工作流，方便录制展示。方向类决定只能由人给——说得越具体，下一轮越不跑偏。

- **你做**：明确内容类型、风格参照、最终用途（自看 / 展示 / 发布），一次说清。
- **AGENT 做**：按新方向重写剧情、角色设定和分镜提示词，准备建正式工程。

### 4. 把新要求做成正式工程

Codex 创建《别开门》画布：先文案（剧情、角色设定、分镜提示词），再生成——两位角色定妆图、一张场景图、三张分镜首帧、三段视频，全部按第 03 节的左→中→右结构落在同一工程里。

- **你做**：逐镜验收；某个任务失败时确认处理方式。本次双人首帧超时，作者确认“只重跑这一张”。
- **AGENT 做**：编排全部生成任务，失败后先排查原因，保留已成功的素材，只定点重跑。
- **✓ 检查点**：去 Muse 网页核对：画布里的每张图、每段视频，都能在 Muse 的生成记录里找到对应条目（能看到上传的参考图、动作要求和返回结果）。对得上，链路才可信。

### 5. 上时间线，拼成片

三个镜头进入本地时间线，加上剧情字幕，拼成 18 秒的《别开门》。工程里同时保留可编辑时间线和全部素材，之后想改任何一镜都能回溯。全程作者没有手写剧本，也没有手工设计分镜——他的工作就是提目标和给反馈。

- **你做**：看成片、定字幕文案、决定是否继续扩镜头或补配音。
- **AGENT 做**：剪辑拼接、加字幕、整理工程文件。

## ⑥ 直接拿去用的指令

给 Agent 的接入指令（按原文流程整理）。把这段发给你的 Agent（原文作者用的是 Codex），把画布名换成你实际用的即可。软件版本和账号状态会变，让 Agent 以它读到的当前文档和你的电脑环境为准。

```
我有 Muse 账号，想把它的图片和视频生成能力接进本地无限画布，画布先用 BeefTV。请读取 BeefTV 和 muse2api 的当前文档，检查我的电脑环境和接口兼容情况，告诉我需要配合哪些步骤，再帮我完成接入。保留已有项目与配置，先验证一张图片，再验证一个视频任务。生成会使用我的账号额度，提交前让我确认，失败后先排查原因。
```

- **测试跑通后，纠正方向这样说**：链路没问题，但内容不是我要的：我要的是 `真人漫剧型` 的内容，并且保留 `真实的画布工作流`，方便我录制展示。把“类型”和“用途”说具体，比说“再好看一点”有用得多。
- **扩成正式工程前，先立一条规矩**：先只跑通 `一个镜头`：图片能生成、首帧能用于视频、结果能回到画布——三件都确认了，再扩成多镜头工程。某个镜头失败时只重跑那一个，别整批重来。

## ⑦ 局限与避坑

原文作者自己列出的真实情况，照着做之前先知道：

- **细节会漂移**：本次成片里人物的痣、疤痕和场景的门窗位置都有漂移。参考图是锚点，但不是保险——每一步生成后都要验图。
- **还没有配音和口型**：这条流程目前只到“画面＋字幕”。更长的剧情、配音、口型是作者计划下一步尝试的方向，尚未在原文中跑通。
- **生成任务会失败**：超时、失败都出现过。正确处理是先排查原因、定点重跑单个任务，保留已成功的结果，而不是全部推倒。
- **“免费”指的是自己账号当时的可用额度**：不是无限次生成，也不能把额度简单换算成“能做多少段视频”。每次提交生成前，先确认会消耗自己的额度。
- **muse2api 是第三方接入，不是官方 API**：它只做连接和转交，生成仍走你的 Muse 账号。使用前先读项目当前文档，确认你接受这种接入方式。
- **换画布不能照搬**：这次用的是 BeefTV。换其他无限画布时，要分别检查素材导入、参考关系、模型接入和剪辑能力四件事。
