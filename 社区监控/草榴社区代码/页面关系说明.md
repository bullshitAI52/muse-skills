# 五个页面的关系与联动现状

[返回代码目录](README.md) · [返回项目记录](../草榴社区.md)

## 先说结论

这五个 HTML 文件是五张独立的说明与记录页面，不是一套已经连接好的系统。放在同一个文件夹中，不会自动共享数据、发送通知、检查远端状态或执行注册。

下面说明的是现有页面的职责和数据边界，不是破解或自动注册操作指南。`1024RegisterTool` 不接入这组页面，仅作为历史源码归档。

## 每个页面负责什么

| 页面 | 在这组资料中的角色 | 现有实现的边界 |
| --- | --- | --- |
| 监控手册（分享版） | 阅读总体规则和本地输入检查说明 | 页面存在不代表后台有监控任务；本地格式检查不代表数据有效 |
| 带掩码的码只原样通知 | 原文登记、备注和记录整理 | 内容缺失时保持原样，不补全；登记与复制不等于通知已经送达 |
| 收到码发邮箱或网盘 | 整理要交接的文本、生成邮件交接内容 | `mailto:` 只尝试打开本机邮件客户端，不是后台发信；没有据此确认网盘上传成功 |
| 单独测试邀请码 | 保存用户手动填写的状态和备注 | 名称中的“测试”不代表已接入远端验证接口；本地结果不能证明网站认可 |
| 测试完能用再去注册（分享版） | 汇总手动填写的处理状态 | 标记状态不等于完成网站操作，也不代表自动注册成功 |

## 信息目前如何流转

目前只能由用户复制、粘贴或使用页面已有的导出能力交接信息。不同页面的输入框、记录列表和状态各自独立，没有共享数据库，也没有后台任务队列。

- **手册与登记页**：手册提供规则说明；登记页中的数据不会自动回写手册。
- **登记页与交接页**：原文、来源和备注需要手动整理；不得把残缺内容补成猜测值。
- **交接页与状态页**：邮件是否发送、是否收到回复，要在实际邮件工具中核实。网页显示的提示不能代替送达确认。
- **两个状态页之间**：状态需要人工核对，不能因为一个页面被标成“有效”，就在另一个页面声称操作成功。

建议每条记录至少保留：记录编号、原文、来源、记录时间、人工备注和状态依据。不要加入密码、Cookie、验证码或账号凭据。实际敏感记录也不要提交到本公开仓库。

## 目前缺少哪些真正的联动能力

| 能力 | 当前状态 |
| --- | --- |
| 五个页面共享记录 | 未实现 |
| 刷新、关闭后统一恢复进度 | 未确认实现，不应依赖 |
| 后台持续监控 | 本代码包未提供相应服务 |
| 自动发送邮件或上传网盘 | 未验证；不能把打开邮件客户端视为完成发送 |
| 远端状态校验、账户操作 | 未接入，不从本地格式或手动标签推断结果 |
| Muse 或 Telegram 接入 | 未实现 |

此外，各页面对长度、字符及掩码的校验规则存在差异，因此不能把一个页面的“通过”直接当成另一个页面的可靠输入结论。

## 旧项目为什么单独放

`1024RegisterTool` 的枚举尝试及外部验证码识别与这组资料“不猜码、不批量尝试”的规则不同。它的存在只补充历史源码，不构成这五页必需的运行依赖，也没有被调用。

本说明不提供枚举破解、验证码绕过或批量注册的接入方案。遇到网站的注册限制，应使用其正式提供的渠道；资料整理不能代替访问授权。

## 验证范围

本说明依据静态源码检查整理，没有执行五个页面，没有连接第三方网站或账户，也未实际发送邮件。要判断交互是否正常，需要另行进行不涉及真实凭据的界面测试。
