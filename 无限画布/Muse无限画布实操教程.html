02

先分工，后动手

搞不清谁干什么，后面每一步都会乱。整条链路一共五个角色：

你导演 / 甲方
做决定的人

提出目标、看效果、纠正方向，确认哪个任务要重试。做什么内容、想怎么展示，只有你能定。

CodexAgent · 编排者
干活的人

安装和接入工具，写剧情、角色设定与分镜提示词，在画布上搭节点、编排生成任务，接口不匹配时做适配。

Muse生成引擎
出图 / 出视频

真正生成图片和视频的是它。画布里发起的每个任务，在 Muse 网页里都能找到对应的生成记录，可逐条核对。

无限画布BeefTV · 工程管家
存素材 / 存关系

保存角色图、场景图、首帧、视频和时间线，并用连线记录“谁参考了谁”。换其他画布时，接法不能直接照搬，要逐项核对导入、参考关系、模型接入和剪辑能力。

muse2api第三方桥接
只负责转交

把画布的提示词、参考图等请求转交给 Muse，等生成完成再把结果送回画布。它不生成内容，消耗的是你自己 Muse 账号的额度，也不是官方提供的免费 API。

04

部署：在 MacBook 上把三件套跑起来

整套东西都在你自己的 MacBook 本地运行，不用租服务器。顺序是：先装画布 BeefTV，再用 Docker 跑 muse2api，然后导号、接入、验证。装的过程也可以直接交给 Agent 做（指令在第 06 节），下面是手动核对用的步骤。

1

装 BeefTV（无限画布）

去 BeefTV 的 GitHub 仓库 Releases 页下载 Mac 桌面版安装包（链接在文末）。这个安装包没有经过苹果公证，第一次双击打不开是正常的。

你做下载并安装；被系统拦下时，去「系统设置 → 隐私与安全性」，在页面下方点「仍要打开」，再确认一次。
✓ 检查点打开后直接进入本地工作区，不需要注册账号，能新建一张空白画布，就算装好了。
2

用 Docker 跑 muse2api

先装好 Docker Desktop 并确认它在运行，然后打开「终端」，依次执行下面四行：

git clone https://github.com/czg86389-hub/muse2api.git cd muse2api cp .env.example .env docker compose up -d
你做打开刚复制出的 .env 文件，把 MUSE2API_KEY 填成一串你自己定的密码（随便一串字符即可，记住它，下一步要用），保存后重新执行一次 docker compose up -d。
✓ 检查点浏览器打开 http://localhost:18610/admin?key=你填的KEY，能看到 muse2api 控制台，服务就是起来了。
3

导号：把 Muse 登录态导进去

muse2api 本身不生成内容，它要借你已登录的 Muse 网页账号干活，所以要把登录态导给它。

你做按 muse2api 项目文档装好它配的 Chrome 扩展，在浏览器里保持 Muse 网页为已登录状态，用扩展把登录态导入 muse2api。
✓ 检查点控制台里能看到账号已接入。登录态 48 小时自动续期，过期或失效时重新导一次即可。
4

在 BeefTV 里接入，再验证

最后把画布和桥接连起来：在 BeefTV 的模型配置里，把 Muse 的图片、视频生成指向 muse2api 的本机地址 http://localhost:18610。

你做填好地址和第 2 步定的 KEY，保存配置。涉及账号额度的生成提交，先自己确认再发。
✓ 检查点先在画布里生成一张图片，能出图；再发一个视频任务，能返回结果。两个都通，部署才算完成，接下来按第 05 节五步实操开做。
跑起来之后，三件事别忘
  • MacBook 睡眠或合盖会断掉本地服务，生成跑到一半别合盖。
  • 18610 端口只在本机用，不要对外暴露。
  • muse2api 是第三方桥接、不是官方 API，消耗的是你自己 Muse 账号的额度，这类接入方式本身有封号风险，先想清楚再用。
05

五步实操

原文的真实顺序。注意第 2 步的“跑偏”不是失败——先拿一个小测试跑通链路，再纠正方向，是这套方法的一部分。

1

让 Agent 把工具搭起来

作者的起点是：看到别人演示 Muse＋无限画布，自己已有 Muse 账号，想在本地复现。他把目标告诉 Codex 并选了“直接安装 BeefTV、接入 Muse”，之后的安装、接口检查都由 Agent 处理；这次视频接口的请求格式并不直接匹配，也是 Agent 做的适配。

你做说明目标和已有条件（有 Muse 账号、画布用 BeefTV），按提示配合完成工作区连接与本机账号接入。
AGENT 做读 BeefTV 与 muse2api 的当前文档，检查电脑环境与接口兼容性，完成安装与适配。
✓ 检查点先验证一张图片能生成，再验证一个视频任务能返回。两个都通，才算接通。涉及账号额度的提交，先经你确认。
2

自动建画布，先跑一次完整测试

接通后先别急着做正片。作者让 Codex 自动建画布，跑了一轮文生图＋图生视频，产物是一组咖啡广告：产品图、海报和一段视频，提示词与结果都留在画布里——目的是验证整条链路真的通。

你做给一个简单、好判断对错的测试题（比如一个产品广告），看完整结果。
AGENT 做建画布、组织节点、发起生图与生视频任务，全程走 Muse 的模型。
✓ 检查点图能出、首帧能喂给视频、视频能回到画布。三件都成立再进下一步。
3

看结果，把方向说具体

咖啡广告跑通了，但不是作者想要的。他给的反馈是两句很具体的话：想要“真人漫剧型”的内容；并且希望有真实的画布工作流，方便录制展示。方向类决定只能由人给——说得越具体，下一轮越不跑偏。

你做明确内容类型、风格参照、最终用途（自看 / 展示 / 发布），一次说清。
AGENT 做按新方向重写剧情、角色设定和分镜提示词，准备建正式工程。
4

把新要求做成正式工程

Codex 创建《别开门》画布：先文案（剧情、角色设定、分镜提示词），再生成——两位角色定妆图、一张场景图、三张分镜首帧、三段视频，全部按第 03 节的左→中→右结构落在同一工程里。

你做逐镜验收；某个任务失败时确认处理方式。本次双人首帧超时，作者确认“只重跑这一张”。
AGENT 做编排全部生成任务，失败后先排查原因，保留已成功的素材，只定点重跑。
✓ 检查点去 Muse 网页核对：画布里的每张图、每段视频，都能在 Muse 的生成记录里找到对应条目（能看到上传的参考图、动作要求和返回结果）。对得上，链路才可信。
5

上时间线，拼成片

三个镜头进入本地时间线，加上剧情字幕，拼成 18 秒的《别开门》。工程里同时保留可编辑时间线和全部素材，之后想改任何一镜都能回溯。全程作者没有手写剧本，也没有手工设计分镜——他的工作就是提目标和给反馈。

你做看成片、定字幕文案、决定是否继续扩镜头或补配音。
AGENT 做剪辑拼接、加字幕、整理工程文件。
06

已复制，去发给你的 Agent 吧
测试跑通后，纠正方向这样说链路没问题，但内容不是我要的：我要的是 真人漫剧型 的内容，并且保留 真实的画布工作流，方便我录制展示。把“类型”和“用途”说具体，比说“再好看一点”有用得多。
扩成正式工程前，先立一条规矩先只跑通 一个镜头：图片能生成、首帧能用于视频、结果能回到画布——三件都确认了，再扩成多镜头工程。某个镜头失败时只重跑那一个，别整批重来。
07

局限与避坑

原文作者自己列出的真实情况，照着做之前先知道：

  • !
    细节会漂移本次成片里人物的痣、疤痕和场景的门窗位置都有漂移。参考图是锚点，但不是保险——每一步生成后都要验图。
  • !
    还没有配音和口型这条流程目前只到“画面＋字幕”。更长的剧情、配音、口型是作者计划下一步尝试的方向，尚未在原文中跑通。
  • !
    生成任务会失败超时、失败都出现过。正确处理是先排查原因、定点重跑单个任务，保留已成功的结果，而不是全部推倒。
  • ¥
    “免费”指的是自己账号当时的可用额度不是无限次生成，也不能把额度简单换算成“能做多少段视频”。每次提交生成前，先确认会消耗自己的额度。
  • ≠
    muse2api 是第三方接入，不是官方 API它只做连接和转交，生成仍走你的 Muse 账号。使用前先读项目当前文档，确认你接受这种接入方式。
  • ✓
    换画布不能照搬这次用的是 BeefTV。换其他无限画布时，要分别检查素材导入、参考关系、模型接入和剪辑能力四件事。
